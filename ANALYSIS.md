## 2. Conventions Found

### Backend
| Convention | Detail |
|---|---|
| **Primary keys** | `UUID(as_uuid=True)`, default `uuid.uuid4`, indexed |
| **Timestamps** | `DateTime(timezone=True)`, `server_default=func.now()`, `onupdate=func.now()` for `updated_at` |
| **Naming** | Table names: plural lowercase (`users`, `profiles`, `courses`, `modules`). Model classes: singular PascalCase. |
| **Base class** | All models subclass `app.core.db.Base` (DeclarativeBase) |
| **Model registration** | Every model module must be imported in `models/__init__.py` AND in `alembic/env.py` |
| **Relationships** | `lazy="noload"` everywhere; explicitly use `selectinload()` in queries |
| **Schema style** | Pydantic v2 BaseModel with `model_config = {"from_attributes": True}` for responses. `Field(...)` with examples/descriptions. Validators use `@field_validator`. |
| **Router style** | `APIRouter(prefix="/api/v1/<resource>", tags=["<resource>"])`. Imported lazily in `create_app()` to avoid circular imports. |
| **RBAC** | `get_current_user` (any authenticated user) and `require_roles(*allowed)` (factory returning a dependency). Used either as `Depends(require_roles(...))` on the parameter or in `dependencies=[...]`. |
| **DB session** | `get_db()` yields `AsyncSession`. Auto-commits on success, rollbacks on exception. |
| **Error style** | `HTTPException` with `status_code` and `detail` string. 404 hides existence ("not found"), 409 for conflicts, 403 for RBAC. |
| **Flush pattern** | `db.add(obj)` → `await db.flush()` → `await db.refresh(obj)` → return ORM object. Commit happens in `get_db()` context manager. |

### Frontend
| Convention | Detail |
|---|---|
| **API client** | `apiClient` (Axios) from `src/api/client.ts`. Base URL from `VITE_API_URL`. Interceptors: attach Bearer token, redirect to `/login` on 401. |
| **Auth** | Tokens in `localStorage` (`access_token`, `refresh_token`). `useAuth()` hook via TanStack Query. |

## 3. Auth / RBAC Flow

1. **Login**: `POST /api/v1/auth/login` → returns `{access_token, refresh_token, token_type}`.
2. **Frontend stores** tokens in `localStorage`.
3. **Axios interceptor** attaches `Authorization: Bearer <access_token>` to every request.
4. **Backend `get_current_user`**: Extracts Bearer token → `decode_token()` → verifies `type == "access"` → loads User from DB → checks `is_active`.
5. **`require_roles(*allowed)`**: Wraps `get_current_user`, additionally checks `user.role in allowed_set`.
6. **Token refresh**: `POST /api/v1/auth/refresh` with refresh token body → new pair (rotation).
7. **401 interceptor**: On 401, clears tokens and redirects to `/login`.

**Roles**: `student`, `lecturer`, `counsellor`, `admin` (stored as PostgreSQL enum `userrole`).

## 4. Patterns to Reuse

- **Model template**: UUID PK, created_at/updated_at timestamps, `Base` subclass, `__repr__`.
- **Router registration**: Lazy import inside `create_app()` with `# noqa: E402`.
- **Schema `__init__.py`**: Re-export all schemas for convenience imports.
- **`selectinload` + `populate_existing`**: Used in `users.py` to reload relationships in the same session.
- **`get_db()` dependency**: Already provides transaction management.
- **`ProtectedRoute` with `allowedRoles`**: Frontend RBAC guard.

### 5.2 No `enrollments` table
The prompt says "Feature 4: Enrolment management" belongs to Member 1, but there is no enrolment table or model in the codebase. I must create it for my features (assignments, quizzes, attendance, weekly aggregation all need student-course relationships). I will create it as a minimal table with a clear comment "owned by Member 1 — extend, do not duplicate".

### 5.3 No `start_date` on Course
The `courses` table has no `start_date` or `end_date` columns. The weekly aggregation job needs a week-0 anchor. **Decision**: I will add `start_date` and `end_date` columns (nullable, Date type) to the `courses` table via migration. This is a non-breaking additive change.

### 5.4 `modules.content_payload` uses `JSON` not `JSONB`
The module model uses `sa.JSON` (not `JSONB`). This means no PostgreSQL JSON operators for indexing/querying. This is fine for read-only content rendering; I will not change it.

### 5.5 `get_db()` auto-commits
The `get_db()` dependency auto-commits on success. This means endpoints should NOT manually call `await db.commit()` — the context manager handles it. Multiple flushes in one endpoint are safe.

### 5.6 APScheduler installed but unused
`apscheduler==3.10.4` is in `requirements.txt` but not configured. The `jobs/` directory has only `__init__.py`. I will set up the scheduler in the lifespan hook.

### 5.7 Frontend `node_modules` only in container
The `docker-compose.yml` mounts `./frontend:/app` with `/app/node_modules` as an anonymous volume. VS Code will show red squiggles for imports. Must verify through the container.

### 5.8 No course update endpoint
The `courses.py` router has `CourseUpdate` schema imported but no `PATCH`/`PUT` endpoint. I will not add it (not my scope), but I note it because I am adding `start_date`/`end_date` to Course.

### 5.9 PowerShell environment
Host OS is Windows with PowerShell. `&&`, `||`, and `curl` (aliased to `Invoke-WebRequest`) behave differently. Use `;` as statement separator, `Invoke-RestMethod` for HTTP calls, `docker exec -i` (not `-it`).
